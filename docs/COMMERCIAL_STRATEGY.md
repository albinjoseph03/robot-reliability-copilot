# Commercial hypotheses (not implemented)

Keep the Apache-2.0 offline CLI useful: local analysis, evidence, JSON exports,
reproducible rules and extensibility should not require an account.

| Hypothesis | Validate before building |
| --- | --- |
| Teams pay for continuous fleet monitoring and incident history | Interview operators about recurring incidents, current costs and retention needs |
| Release regression reports reduce verification effort | Compare two permitted releases on labeled, reproducible scenarios and measure saved engineer time |
| Shared incident review and integrations help teams | Observe a real debugging handoff and identify repeated manual steps |
| Hosted analysis saves setup time | Test demand for opt-in upload while assessing privacy and deployment constraints |
| Private deployment and support serve regulated/private fleets | Ask for concrete deployment requirements and willingness to pilot with a budget |

Early measures: time to first useful report, fraction of findings accepted or
rejected by engineers, repeated use over several releases, reproducible issue
submissions, and requests for a paid pilot. Stars and downloads alone do not
validate a business. Never imply that an incident finding certifies safety.

Revisit product scope after real ROS validation and user interviews. No
commercial infrastructure, tracking, upload workflow or paid feature is part
of v0.1.
